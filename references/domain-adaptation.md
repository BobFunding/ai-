# 분야별 적용 예시

아래 예시는 선택 가능한 매핑이다. 실제 사용자 과업과 기존 앱 구조가 우선이다.

| 분야 | 첫 결과 | 입력·작은 실행 | 피드백·검토 | 완료·다음 행동 |
| --- | --- | --- | --- | --- |
| 광고·콘텐츠 | 캠페인 초안 | 브리프 → 문구 작성 | 원안/개선안, 수정 이유 | 승인 → 게시 준비·성과 점검 |
| 교육 | 한 문제의 이해 | 예시 → 직접 답변 | 오답 이유·개선 표현 | 학습 저장 → 적절한 복습 |
| 예약 | 확정 가능한 예약 | 서비스·시간 선택 | 일정·비용·취소 조건 검토 | 예약 완료 → 일정 확인 |
| 쇼핑 | 조건에 맞는 상품 | 요구 조건 → 비교 | 차이·가격·선택 이유 | 주문 검토 → 주문·배송 상태 |
| 생활비 관리 | 정리된 지출 | 자료 입력 → 분류 | 분류 근거·사용자 수정 | 저장 → 다음 정리 시점 |
| 운동 기록 | 실행 가능한 운동 계획 | 상황·가능 시간 → 계획 | 강도·실행 가능성 수정 | 기록 → 다음 운동 |
| 프로젝트 관리 | 다음 할 일 | 목표 → 작업 분해 | 누락·우선순위 검토 | 계획 저장 → 수행·회고 |

## 변환 판단 예시

- 예약에서는 피드백 단계를 별도 AI 평가로 만들 필요가 없다. 예약 정보 확인이 검토 역할을 한다.
- 운동이나 일정 계획에는 재점검이 유용하지만 일회성 구매 완료 후 “반복하기”를 강요하지 않는다.
- 자료가 없을 때 예시 체험을 제공할 수 있다. 실제 결과와 샘플 데이터를 구분하고, 실제 작업으로 전환하는 진입점을 마련한다.
- 음성이나 사진 입력이 핵심이면 해당 시점에 권한 이유를 설명하고, 서비스상 가능한 텍스트·파일 대안을 제공한다.
- 전문가 판단이 필요한 분야에는 일반적인 UX 흐름만 적용한다. 스킬의 피드백 구조를 전문적 정확성이나 개인 맞춤 처방의 근거로 사용하지 않는다.

## 화면 명세를 작성할 때

필요한 각 화면마다 아래 질문에 답하면 설계와 구현을 연결할 수 있다.

1. 사용자가 이 화면에서 얻거나 결정할 것은 무엇인가?
2. 필수 입력은 무엇이며 예시 체험으로 대체할 수 있는가?
3. 주요 버튼은 어떤 상태에서 활성화되고 무엇을 실행하는가?
4. 다음 단계로 넘어갔다는 증거는 무엇인가?
5. 실패·뒤로 이동·재접속 시 무엇을 보존하는가?
6. 결과 확정 후 사용자의 다음 행동이 정말 필요한가?
